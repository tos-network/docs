# BlockDAG: Revolutionizing Blockchain Scalability

TOS Network's **BlockDAG (Directed Acyclic Graph)** architecture represents a fundamental breakthrough in blockchain scalability, moving beyond traditional linear chains to enable **parallel block creation** and **enhanced network throughput**. This innovation embodies TOS's core principle of **"Don't Trust, Verify it"** by maintaining cryptographic verification while dramatically improving performance.

## What is BlockDAG?

A BlockDAG is an advanced blockchain structure that allows **multiple blocks to exist at the same height simultaneously**, creating a more flexible and scalable network topology compared to traditional linear blockchains.

### Traditional Blockchain vs BlockDAG

```
Traditional Linear Blockchain:
Block 1 → Block 2 → Block 3 → Block 4 → Block 5
(Only one block per height, bottleneck)

TOS BlockDAG:
         Block 2a ←─┐
        ↗            ├─→ Block 4a → Block 5
Block 1 → Block 2b ←─┘   ↗
        ↘            ┌─→ Block 4b ↗
         Block 2c ←─┘
(Multiple blocks per height, parallel processing)
```

### Key Benefits

- 🚀 **Higher Throughput**: Process 2,500+ transactions per second
- ⚡ **Faster Confirmations**: Reduced confirmation times through parallel validation
- 🔄 **Reduced Orphans**: Side blocks still contribute to network security
- 🛡️ **Enhanced Security**: Multiple validation paths increase attack resistance
- 📈 **Better Scalability**: Network capacity grows with participation

## Topological Ordering

TOS BlockDAG uses **topological ordering** to establish a consistent sequence of blocks within the DAG structure:

### Topoheight System

Every block receives a **topoheight** - a deterministic position in the topological order:

```rust
pub struct Block {
    pub height: u64,        // Traditional block height
    pub topoheight: u64,    // Position in topological order
    pub cumulative_difficulty: u128,
    pub tips: Vec<Hash>,    // References to previous blocks (up to 3)
}
```

### Dynamic Ordering

The topological order can change until blocks reach **stable height**:

```
Example Reorganization:
Initial Order:  [Block A: topo=100] → [Block B: topo=101]
After Reorg:    [Block B: topo=100] → [Block A: topo=101]

Reason: Block B achieved higher cumulative difficulty
```

### Deterministic Selection

When multiple blocks compete for the same position:

1. **Cumulative Difficulty**: Higher difficulty wins
2. **TIPS Quality**: Better connected blocks preferred
3. **Timestamp**: Earlier blocks favored in ties
4. **Hash Value**: Deterministic tie-breaker

## Stable Height Mechanism

To prevent deep reorganizations and maintain network stability:

### Stability Rules

```rust
pub const STABLE_LIMIT: u64 = 8;

impl BlockDAG {
    pub fn calculate_stable_height(&self, current_top: u64) -> u64 {
        // Stable height is always 8 blocks behind the top
        current_top.saturating_sub(STABLE_LIMIT)
    }

    pub fn is_block_stable(&self, block_topoheight: u64) -> bool {
        block_topoheight <= self.get_stable_height()
    }
}
```

### Stability Guarantees

- ✅ **Irreversible**: Blocks below stable height cannot be reorganized
- ✅ **Predictable**: Applications can rely on stable transactions
- ✅ **Secure**: Deep reorganization attacks are prevented
- ✅ **Final Settlement**: Financial applications have clear finality

## Consensus Rules and TIPS Selection

### TIPS Selection Algorithm

Miners select up to **3 TIPS** (heaviest chain endpoints) as previous blocks:

```rust
impl TIPSSelector {
    pub fn select_tips(&self, available_tips: &[BlockHash]) -> Vec<BlockHash> {
        let mut selected = Vec::new();

        // Sort by cumulative difficulty
        let mut sorted_tips = available_tips.clone();
        sorted_tips.sort_by(|a, b| {
            self.get_cumulative_difficulty(b)
                .cmp(&self.get_cumulative_difficulty(a))
        });

        // Select up to 3 TIPS with difficulty constraints
        for tip in sorted_tips {
            if selected.len() >= 3 { break; }

            if self.validate_difficulty_difference(&selected, &tip) {
                selected.push(tip);
            }
        }

        selected
    }

    fn validate_difficulty_difference(&self, existing: &[BlockHash], new_tip: &BlockHash) -> bool {
        // Maximum 9% difficulty difference between selected TIPS
        for existing_tip in existing {
            let diff_ratio = self.calculate_difficulty_ratio(existing_tip, new_tip);
            if diff_ratio > 0.09 { return false; }
        }
        true
    }
}
```

### Transaction Handling

The same transaction can appear in multiple blocks:

```rust
pub struct TransactionExecutor {
    executed_transactions: HashSet<TransactionHash>,
}

impl TransactionExecutor {
    pub fn execute_block_transactions(&mut self, block: &Block) -> ExecutionResult {
        let mut results = Vec::new();

        for tx in &block.transactions {
            if !self.executed_transactions.contains(&tx.hash) {
                // Execute transaction for the first time
                let result = self.execute_transaction(tx)?;
                self.executed_transactions.insert(tx.hash.clone());
                results.push(result);
            } else {
                // Transaction already executed in another block
                results.push(ExecutionResult::AlreadyExecuted(tx.hash.clone()));
            }
        }

        Ok(results)
    }
}
```

## Implementation Details

### Block Validation Process

```rust
pub struct BlockValidator {
    dag: Arc<BlockDAG>,
}

impl BlockValidator {
    pub async fn validate_block(&self, block: &Block) -> ValidationResult {
        // 1. Basic structural validation
        self.validate_structure(block)?;

        // 2. Proof of work validation
        self.validate_proof_of_work(block)?;

        // 3. TIPS validation
        self.validate_tips_selection(block)?;

        // 4. Transaction validation
        self.validate_transactions(block)?;

        // 5. DAG consistency check
        self.validate_dag_consistency(block)?;

        Ok(ValidationResult::Valid)
    }

    fn validate_tips_selection(&self, block: &Block) -> Result<(), ValidationError> {
        // Verify TIPS selection follows consensus rules
        if block.tips.len() > 3 {
            return Err(ValidationError::TooManyTips);
        }

        // Check difficulty differences
        for i in 0..block.tips.len() {
            for j in (i+1)..block.tips.len() {
                let diff_ratio = self.calculate_difficulty_ratio(&block.tips[i], &block.tips[j]);
                if diff_ratio > 0.09 {
                    return Err(ValidationError::TipsDifficultyTooHigh);
                }
            }
        }

        Ok(())
    }
}
```

### State Management

```rust
pub struct DAGState {
    blocks: BTreeMap<u64, Vec<Block>>,  // height -> blocks
    topoheight_to_block: BTreeMap<u64, BlockHash>, // topoheight -> block
    tips: HashSet<BlockHash>,
    stable_height: u64,
}

impl DAGState {
    pub fn add_block(&mut self, block: Block) -> Result<(), StateError> {
        // Update blocks at height
        self.blocks.entry(block.height).or_default().push(block.clone());

        // Recalculate topological order
        self.recalculate_topological_order()?;

        // Update TIPS
        self.update_tips(&block);

        // Update stable height
        self.update_stable_height();

        Ok(())
    }

    fn recalculate_topological_order(&mut self) -> Result<(), StateError> {
        // Implement topological sort with cumulative difficulty tiebreaker
        let sorted_blocks = self.topological_sort_with_difficulty()?;

        self.topoheight_to_block.clear();
        for (topo_height, block_hash) in sorted_blocks.iter().enumerate() {
            self.topoheight_to_block.insert(topo_height as u64, *block_hash);
        }

        Ok(())
    }
}
```
